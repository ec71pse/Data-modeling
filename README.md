# Моделирование данных для интернет-магазина

## Обзор проекта

Данный проект посвящен проектированию логической модели данных для интернет-магазина одежды одного бренда. Целью проекта было преобразование бизнес-требований в нормализованную модель базы данных, которая может служить основой для дальнейшей разработки системы.

В рамках проекта были выполнены анализ требований, моделирование пользовательских сценариев, концептуальное и логическое моделирование данных, валидация связей между сущностями и нормализация модели до третьей нормальной формы (3НФ).

---

## Постановка задачи

При проектировании модели необходимо было учесть следующие бизнес-правила:

- магазин продает одежду только одного бренда;
- данные банковских карт пользователей не хранятся;
- на отдельные товары могут распространяться акции с фиксированной скидкой;
- один товар может участвовать только в одной акции;
- пользователь должен видеть как первоначальную, так и цену со скидкой.

---

## Моя роль — Системный аналитик

В рамках проекта я отвечал за:

- анализ предметной области и бизнес-правил;
- выявление сущностей предметной области и связей между ними;
- моделирование пользовательских сценариев с использованием UML Use Case Diagram;
- подготовку подробных спецификаций вариантов использования (Use Case Specification);
- разработку концептуальной ER-модели в нотации Чена;
- преобразование концептуальной модели в логическую модель данных в нотации Crow's Foot;
- проверку корректности связей, кардинальностей и ограничений;
- нормализацию модели данных до третьей нормальной формы (3НФ).

## Логическая ER-модель (нотация Crow's Foot)

Концептуальная модель была преобразована в логическую модель данных с использованием нотации Crow's Foot.

Модель включает основные сущности системы:

- Пользователь;
- Заказ;
- Товар;
- Акция;
- Оплата;
- Доставка;
- Товар в заказе.

## Валидация модели данных

После построения логической модели была проведена проверка:

- корректности связей между сущностями;
- правильности кардинальностей;
- отсутствия избыточности данных;
- соответствия бизнес-требованиям.

Итоговая модель была приведена к **третьей нормальной форме (3НФ)**.

## Итоговый результат

В результате проекта был подготовлен полный комплект артефактов системного анализа для проектирования базы данных интернет-магазина:

- UML-диаграмма вариантов использования (Use Case Diagram);
- спецификации вариантов использования (Use Case Specification);
- концептуальная ER-диаграмма (нотация Чена);
- логическая ER-диаграмма (нотация Crow's Foot);
- результаты валидации модели данных;
- логическая модель базы данных, приведенная к третьей нормальной форме (3НФ).
